## Контрольные вопросы

**1. Чем `Queue<T>` отличается от `Stack<T>` и когда применяется каждый?**
`Queue<T>` — очередь, принцип FIFO (первый пришёл — первый ушёл). Применяется, когда нужно обрабатывать заказы в порядке поступления. `Stack<T>` — стек, принцип LIFO (последний пришёл — первый ушёл). Применяется для истории действий, чтобы отменять последнее действие первым.

**2. Зачем сохранять узел, возвращённый `AddLast`, вместо повторного поиска через `Find`?**
`AddLast` возвращает `LinkedListNode`, на который можно сразу сослаться при вставке через `AddAfter`. `Find` каждый раз обходит весь список с начала, что медленно, особенно если элементов много.

**3. Почему попытка прочитать отсутствующий ключ словаря через индексатор приводит к исключению, и как этого избежать?**
Индексатор `stock[key]` выбрасывает `KeyNotFoundException`, если ключа нет. Избежать можно через `TryGetValue(key, out var value)` или проверку `ContainsKey(key)` перед чтением.

**4. В чём разница между `IComparable<T>` и `IComparer<T>` и что произойдёт при `Sort()` типа без обоих интерфейсов?**
`IComparable<T>` реализуется внутри самого класса и задаёт «естественный» порядок (метод `CompareTo`). `IComparer<T>` — отдельный класс-компаратор для альтернативной сортировки. Если тип не реализует ни один из них, `Sort()` не скомпилируется — programa не будет знать, как сравнивать объекты.

**5. Что такое отложенное (ленивое) выполнение LINQ-запроса и когда реально происходит обход?**
Запрос создаётся, но не выполняется сразу. Элементы обходятся только когда мы начинаем перебирать результат: в `foreach`, `ToList()`, `Count()`, `FirstOrDefault()` и т.д.

**6. Чем отличается `IGrouping<TKey, TElement>` от обычной коллекции и какие операции к нему применимы?**
Это не просто список, а группа с ключом: у неё есть свойство `Key` (название категории) и сама коллекция элементов. К ней применимы `Count()`, `Average()`, `Sum()`, `Select()`, `Where()`, `OrderByDescending()` и другие LINQ-методы.

**7. Как работает `Join` и что произойдёт, если у одного клиента несколько заказов?**
`Join` соединяет две коллекции по общему ключу. Если у клиента несколько заказов, он продублируется — получится несколько строк, по одной на каждый заказ этого клиента.

**8. Почему бесконечный итератор не приводит к зависанию программы, а `Take(N)` ограничивает его работу?**
Итератор с `yield return` вычисляет элемент только тогда, когда его просят (лениво). Бесконечный итератор сам по себе не зависнет — зависнет только попытка перебрать его целиком. `Take(N)` берёт первые N элементов и останавливает перебор, поэтому бесконечность не страшна.

**9. Зачем нужна явная реализация `IEnumerator IEnumerable.GetEnumerator()` в собственном классе коллекции?**
Это нетипизированная версия для совместимости со старым интерфейсом `IEnumerable`. Без неё коллекция может некорректно работать в некоторых ситуациях с `foreach` или при приведении типов.

**10. Как в кольцевом буфере определить индекс самого старого хранящегося элемента?**
Самый старый элемент — тот, который лежит в буфере longest time. Обычно за ним следит отдельный индекс `head`/`start`. При переполнении старые элементы перезаписываются, и индекс старого сдвигается по кругу.

**11. Чем готовый проект с девятью этапами лучше девяти отдельных заданий?**
Постепенно осваиваем язык C#: с самого начала простые коллекции, потом LINQ, потом итераторы. Каждый следующий этап использует навыки предыдущего, поэтому материал закрепляется на практике, а не по отдельным отрывкам. В конце получается целая работающая система, а не набор разрозненных файлов.
