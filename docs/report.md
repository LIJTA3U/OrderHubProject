# Отчёт по этапам 1–2 проекта OrderHub

## Этап 1. КТ 31. Коллекции List<T>, Stack<T>, Queue<T>

### 1. Цель работы

Целью первого этапа было реализовать базовую обработку заказов интернет-магазина OrderHub с использованием трёх коллекций C#: `List<T>`, `Queue<T>` и `Stack<T>`.

В рамках этапа требовалось обеспечить хранение всех созданных заказов, обработку заказов в порядке поступления, ведение истории действий и вывод отчётов в консоль.

### 2. Реализация

В классе `Order` реализованы конструктор с параметрами `Id`, `CustomerName`, `ProductName`, `Price`, `CreatedAt`, свойства только для чтения и переопределённый метод `ToString()`. Для отображения цены используется русская числовая культура, а дата выводится в формате `dd.MM.yyyy`.

В классе `OrderService` реализованы три коллекции:

- `List<Order> allOrders` — хранит все созданные заказы в порядке добавления.
- `Queue<Order> pendingQueue` — хранит необработанные заказы. Метод `Enqueue()` добавляет заказ в конец очереди, а `Dequeue()` извлекает первый заказ.
- `Stack<string> undoHistory` — хранит описания последних действий. Методы `Push()` и `Pop()` обеспечивают работу по принципу LIFO.

Также реализованы методы `CreateOrder()`, `ProcessNext()`, `UndoLastAction()`, `PrintAllOrders()`, `PrintPendingQueue()` и `PrintRecentActions()`.

Метод `CreateOrder()` создаёт заказ с очередным идентификатором, добавляет его в список и очередь, а описание действия сохраняет в стеке. Метод `ProcessNext()` проверяет наличие ожидающих заказов, извлекает первый заказ из очереди, записывает действие в историю и выводит результат обработки. Отчётные методы используют `foreach`.

### 3. Результат выполнения

После создания трёх заказов и обработки двух из них получен следующий результат:

```text
Обработан заказ: #1 Иванов — Клавиатура 5 490,00 ₽ (19.10.2026)
Обработан заказ: #2 Петрова — Монитор 18 990,00 ₽ (19.10.2026)

Все заказы:
#1 Иванов — Клавиатура 5 490,00 ₽ (19.10.2026)
#2 Петрова — Монитор 18 990,00 ₽ (19.10.2026)
#3 Сидоров — Мышь 1 290,00 ₽ (19.10.2026)

Заказов ожидает обработки: 1
Первый в очереди: #3 Сидоров — Мышь 1 290,00 ₽ (19.10.2026)

История последних действий:
Обработан заказ 2
Обработан заказ 1
Создан заказ 3 для Сидоров
Создан заказ 2 для Петрова
Создан заказ 1 для Иванов
```

Проверка подтвердила, что список содержит все три заказа, а в очереди после двух обработок остаётся только заказ Сидорова. История действий выводится от последнего действия к первому.

### 4. Вывод

В ходе первого этапа закреплены навыки работы с коллекциями `List<T>`, `Queue<T>` и `Stack<T>`. Реализована базовая логика учёта и обработки заказов, а также вывод отчётов в консоль.

## Этап 2. КТ 32. Связный список LinkedList<T>

### 1. Цель работы

Цель второго этапа — освоить применение коллекции `LinkedList<T>` для организации истории заказов клиента с возможностью вставки нового заказа сразу после текущего.

Дополнительно требовалось научиться работать с узлами `LinkedListNode<T>`, сохранять ссылку на текущий узел, находить заказ по имени клиента и выводить историю заказов.

### 2. Реализация

В классе `OrderService` добавлены поля:

- `LinkedList<Order> orderHistory` — связный список истории заказов.
- `LinkedListNode<Order>? current` — ссылка на текущий узел. Значение `null` означает, что текущий узел отсутствует.

Реализованы следующие методы:

**`InitHistory(params Order[] orders)`** — очищает предыдущую историю, последовательно добавляет заказы через `AddLast()` и сохраняет ссылку на узел последнего добавленного заказа в поле `current`.

**`PlaceOrderAfterCurrent(Order order)`** — вставляет новый заказ сразу после текущего с помощью `AddAfter()`. После вставки поле `current` указывает на новый узел. Если текущий узел отсутствует, новый заказ добавляется в список через `AddLast()`.

**`TryFindOrder(string customerName, out Order? order)`** — ищет заказ указанного клиента. После определения подходящего объекта метод `Find()` используется для получения узла связного списка. При успешном поиске метод возвращает `true` и передаёт найденный заказ через параметр `out`; если заказ не найден, возвращает `false`.

**`PrintHistory()`** — перебирает заказы с помощью `foreach` и отдельно выводит текущий заказ через `current?.Value`.

### 3. Проверка работы

Для проверки истории создаются два заказа: Иванова и Петровой. После вызова `InitHistory()` текущим становится последний заказ — заказ Петровой.

Затем методом `PlaceOrderAfterCurrent()` добавляется заказ Сидорова. Поскольку вставка выполняется сразу после текущего узла, ожидаемый порядок истории следующий:

```text
История заказов:
#... Иванов — Клавиатура ...
#... Петрова — Монитор ...
#... Сидоров — Мышь ...

Текущий заказ: #... Сидоров — Мышь ...
```

При вызове `TryFindOrder("Иванов", out var found)` ожидается результат `true` и вывод найденного заказа. При вызове `TryFindOrder("Нет такого", out _)` ожидается результат `false`.

### 4. Вывод

В ходе второго этапа изучена работа со связным списком `LinkedList<T>` и узлами `LinkedListNode<T>`. Реализованы добавление заказов в историю, вставка нового заказа после текущего узла, поиск по имени клиента и вывод истории.

Связный список позволяет вставлять элементы относительно существующего узла с помощью `AddAfter()`, не ограничиваясь добавлением только в начало или конец коллекции.

## Этап 3. КТ 33. Dictionary<TKey, TValue>

### 1. Цель работы

Цель третьего этапа — реализовать склад товаров в приложении OrderHub с использованием коллекции `Dictionary<TKey, TValue>`. Требуется поддержать поступление товаров, продажу, удаление из учёта при нулевом остатке и безопасный поиск по названию товара без возникновения `KeyNotFoundException`.

### 2. Реализация

В файле `src/OrderHub/Services/WarehouseService.cs` создан класс `WarehouseService`. Для хранения остатков используется поле `Dictionary<string, int> stock`, где ключ — название товара, а значение — количество единиц на складе.

Реализованы следующие методы:

- **`Receive(string productName, int quantity)`** — проверяет наличие товара с помощью `TryGetValue()`. Если запись уже существует, количество увеличивается; если товар поступил впервые, новая запись создаётся через индексатор словаря. Метод выводит актуальный остаток. Неположительное количество поступления отклоняется.
- **`Sell(string productName, int quantity)`** — сначала проверяет количество и наличие товара через `TryGetValue()`. Если товара нет или остатка недостаточно, метод выводит сообщение и возвращает `false`, не изменяя склад. При успешной продаже остаток уменьшается. Если он становится равен нулю, запись удаляется через `Remove()`; результат удаления проверяется. При успешной операции метод возвращает `true`.
- **`TryGetStock(string productName, out int quantity)`** — выполняет безопасный поиск остатка. Если товар найден, возвращает `true` и его количество. Если товар отсутствует, возвращает `false` и устанавливает `quantity = 0`.
- **`PrintStock()`** — перебирает элементы как `KeyValuePair<string, int>` с помощью `foreach`. Для удобства чтения товары перед выводом сортируются по названию с помощью `OrderBy()`.

В `src/OrderHub/Program.cs` сохранён сценарий работы с заказами предыдущих этапов и добавлены вызовы для демонстрации поступления и продажи товаров. Проверочный сценарий дважды добавляет клавиатуры, добавляет мониторы, выполняет успешную продажу, пытается продать больше имеющегося количества и продаёт отсутствующий товар.

### 3. Проверка работы

В демонстрационном сценарии выполняются вызовы:

```csharp
warehouse.Receive("Клавиатура", 10);
warehouse.Receive("Клавиатура", 5);
warehouse.Receive("Монитор", 3);

warehouse.Sell("Монитор", 1);
warehouse.Sell("Монитор", 99);
warehouse.Sell("Проектор", 1);
warehouse.PrintStock();
```

Ожидаемый вывод складской части программы:

```text
=== Склад товаров (КТ 33) ===
Поступление: Клавиатура. На складе: 10 шт.
Поступление: Клавиатура. На складе: 15 шт.
Поступление: Монитор. На складе: 3 шт.
Продано 1 шт. товара "Монитор". Остаток: 2 шт.
Недостаточно товара "Монитор". На складе: 2 шт., запрошено: 99 шт.
Товар "Проектор" отсутствует на складе.
Клавиатура: 15 шт.
Монитор: 2 шт.
```

Проверочный сценарий показывает, что повторное поступление клавиатуры увеличивает значение существующей записи до 15, а не создаёт дубликат. После продажи одного монитора остаётся 2 штуки. Попытка продать 99 мониторов возвращает `false` и не меняет остаток. Продажа отсутствующего проектора также возвращает `false`; исключение при поиске не возникает. Итоговый список выводится по алфавиту.

Дополнительно метод `TryGetStock()` позволяет проверить отсутствие товара без исключения: для отсутствующего ключа он возвращает `false` и задаёт остаток, равный нулю. Если продать весь остаток конкретного товара, запись удаляется из словаря с помощью `Remove()`.

*Примечание: приведённый вывод — ожидаемый результат по текущему коду сценария; сборка и запуск этапа 3 в этой среде не подтверждены, поскольку .NET SDK недоступен.*

### 4. Вывод

В ходе третьего этапа закреплены навыки работы с `Dictionary<TKey, TValue>`: добавление и изменение значений по ключу, безопасное чтение через `TryGetValue()`, проверка количества перед продажей и удаление записи через `Remove()`. Складской сервис обрабатывает отсутствующий товар и недостаточный остаток без исключений и сохраняет корректные значения после неуспешной продажи.

## Этап 4. КТ 34. IComparable<T>, IComparer<T>. Сортировка

### 1. Цель работы

Цель четвёртого этапа — освоить сортировку объектов в C# с помощью интерфейсов `IComparable<T>` и `IComparer<T>`, а также с использованием лямбда-выражения, соответствующего делегату `Comparison<T>`.

В проекте OrderHub необходимо реализовать сортировку каталога товаров по цене, по названию и по длине названия.

### 2. Реализация

В файле `src/OrderHub/Domain/Product.cs` реализован класс `Product`, содержащий свойства `Name`, `Price` и `Category`, конструктор и переопределённый метод `ToString()`.

Класс `Product` реализует интерфейс `IComparable<Product>`. В методе `CompareTo()` товары сравниваются по цене с помощью `Price.CompareTo(other.Price)`. Это задаёт естественный порядок сортировки по возрастанию цены. Также предусмотрена проверка на `null`.

Для альтернативной сортировки создан класс `NameComparer`, реализующий `IComparer<Product>`. Его метод `Compare()` сравнивает названия товаров с помощью `string.Compare()` и `StringComparison.Ordinal`.

Дополнительно создан класс `PriceDescComparer`, который сортирует товары по убыванию цены. Обратный порядок получается при вызове `b.Price.CompareTo(a.Price)`.

В файле `src/OrderHub/Services/CatalogService.cs` реализовано хранение каталога в `List<Product>` и добавление товаров с помощью `AddProduct()`.

Метод `PrintSortedByNaturalOrder()` сортирует копию списка вызовом `Sort()` без аргументов. Метод `PrintSortedByName()` использует `Sort(new NameComparer())`. Метод `PrintSortedByNameLength()` сортирует копию списка лямбда-выражением:

```csharp
(a, b) => a.Name.Length.CompareTo(b.Name.Length)
```

Это делегат `Comparison<Product>`. При таком подходе класс `Product` не требуется изменять. Для вывода каталога в исходном порядке реализован метод `PrintAll()`.

Сортировочные методы работают с копией списка. Благодаря этому каталог сохраняет первоначальный порядок добавления товаров независимо от выполненных сортировок.

### 4. Вывод

В ходе четвёртого этапа изучены два подхода к сравнению объектов: `IComparable<T>` задаёт естественный порядок внутри класса, а `IComparer<T>` позволяет определять альтернативные правила сортировки отдельно от класса модели.

Также освоена сортировка с помощью лямбда-выражения `Comparison<T>`. Она позволяет применять разовое правило сравнения без изменения типа `Product`.

Реализация каталога демонстрирует сортировку по цене, по названию и по длине названия, сохраняя исходный порядок товаров для последующего вывода.
